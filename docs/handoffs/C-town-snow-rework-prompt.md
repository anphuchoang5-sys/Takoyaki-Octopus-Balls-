## 一 用户明确要的效果

用户点击下雪后，积雪连续经历以下三个阶段；中途不能突然切换成另一套完整白色模型。第一轮先在三个小样中验证这一过程。

| 阶段 | 画面要求 |
| --- | --- |
| 零星附着 | 马路、屋顶和植物的原色、质地仍然清楚，表面逐渐出现细小雪点和不规则雪斑。 |
| 连续薄雪 | 雪斑逐渐扩大并连接，承雪表面的底色被盖住，只看到薄薄一层雪；仍能辨认原物体的轮廓、坡度和台阶。 |
| 厚雪成形 | 在薄雪基础上继续堆积，形成有厚薄差异的雪堆、屋檐雪边和灌木雪帽；拉近或从侧面看都有真实体积，底部贴着承雪物体。 |

地图编辑器要统一控制路面、建筑屋顶及部分通用装饰的雪景。各类物体应共用进度，并按自己的表面和形状响应。

**第一轮优先级是真实贴合。** 雪底应跟随原物体实际表面的高低起伏，薄雪保留细节；随着厚度增加，小瓦缝、叶团凹陷等逐渐被填平，大的坡面与轮廓仍由原物体决定。增加白色、颗粒或表面噪点，不能代替这种贴合关系。

“各阶段占多少时间”“最终堆多厚”“雪粒大小与密度”尚未定稿，不擅自写成用户已经确认的数值。

## 二 已查到的问题

以下为 2026-10-20 对工作区源码及用户截图的静态核对结论，不是运行复测结果；实施前重新核对相关文件。

1. **覆盖一开始就接近整片出现。** 共用雪层使用不透明白色材质，雪量大于零时显示整组雪体，后续主要按雪量升高顶面。没有随雪量增长的零散覆盖过程。
2. **雪层侧壁朝向存在错误。** 共用生成代码的侧壁三角形朝向内部，材质默认仅绘制正面，外侧可能看不到侧壁。这与用户截图的“白面悬在草地上”相符；还需结合底部高度、接缝和实际镜头验证，不能只改朝向就宣称所有悬空问题已解决。
3. **地面与庭院过于整片、均匀。** 现有雪层主要是整格范围加厚度起伏，缺少从原地面逐步附着的表现；地图草叶随雪量缩短，也不能代替草叶逐渐被当地积雪埋住的过程。
4. **建筑和植物的贴合不完整。** 屋顶已有坡面大轮廓，但主要使用手填范围和高度；みつや冰柜雪层使用固定高度，旧交接也记录了斜盖不贴合、厚雪遮招牌等问题。右侧灌木尚无对应的独立雪帽，不能以周围地面雪上涨代替植物承雪。
5. **现有检查不能证明画面符合要求。** 雪量、降水落点、释放资源和存档检查，不覆盖早期材质可见、侧壁朝向、灌木贴合及三阶段视觉变化。

## 三 建议修改措施

### 先依据真实表面建立贴合关系

- 核对每个小样实际可见的表面形状，依据屋面坡度与起伏、灌木叶团和实际路面生成承雪表面；不能只取外包长宽与一个平均高度。
- 检查表面朝向、遮挡与空隙。竖直面、受遮挡区域和叶团间的空隙不能自动按完整平面填满。
- 若瓦纹或路面凹凸只是平面上的图案，需明确哪些高低确实存在、哪些只有画面信息；需要补充的凹凸信息只在隔离小样中处理并说明，不改正式资产来掩盖问题。
- 雪量增加时保持底部接触，薄雪体现原表面起伏，厚雪逐渐填平小凹陷；不得整层向上平移后留下空隙，也不要求厚雪机械复制每一道细缝。

### 先补覆盖过程 再处理厚度

- 继续使用统一 `snowAmount`，分别驱动覆盖程度与厚度；两者不必按相同比例变化。
- 初期采用稳定、不规则的雪点和雪斑分布，让原材质从未覆盖的地方露出来。不要仅把整块白面调整为半透明，那仍容易像蒙了一层白膜。
- 雪斑随进度扩大并连接，先形成连续薄雪，再明显增加厚度。分布不能每帧随机重置，避免闪烁或跳动。
- 厚雪增加柔和体积和边缘变化，但不能仅靠在现有白板上加噪点来代替整个过程。
- 不要求逐颗模拟全部落雪。飘落雪花与表面积雪可以共用全镇进度，通过贴合、覆盖和形状变化完成视觉效果。

### 让雪贴住不同物体

下表保留完整返工方向；第一轮仅验证屋顶、灌木和路面，其余内容不自动纳入小样范围。

| 对象 | 建议措施 |
| --- | --- |
| 马路与铺地 | 薄雪贴合实际路面，早期保留路面纹理和接缝；后期形成厚薄变化，路缘收口柔和，相邻地块不出现方块拼缝或台阶跳变。 |
| 草地 | 雪从地表开始积聚，薄雪间允许草尖露出，厚雪逐渐埋住大部分草叶；边缘不能留下一条能看穿的空隙。 |
| 坡屋顶与平屋顶 | 雪从真实承雪表面生长，顺应屋脊、坡面、檐口和设备轮廓；保留建筑原形，避免与招牌、墙面和屋面细节错误穿插。 |
| 灌木等通用装饰 | 按朝上的叶团分别积雪，逐渐形成圆润雪帽，保留侧面轮廓与部分绿叶；不以地面平板横切灌木，也不把整株直接染白。 |

修正侧壁朝向和底部贴合，检查外边缘及孔洞边缘。简单开启双面显示不能代替正确的体积结构。

积雪位置要尊重表面朝向和遮挡，不让受屋顶遮住的内部区域仅因处于同一地块就自动铺满雪。

### 地图统一控制与建筑配合

用户已明确地图要统一控制雪景。以下是后续正式地图推广的配合方向，具体修改归属仍由用户安排：

- 地图负责全镇积融雪进度、道路与公共地面、通用承雪规则及场景接入。
- 建筑提供准确的承雪位置、形状、需要避开的区域及必要例外；屋顶和灌木可复用共用能力，特殊造型保留局部配置。
- 同一处雪面只生成一份；不能地图和建筑各铺一层。
- 继续沿用“一栋建筑一个文件夹”，不另造复杂框架。

## 四 保留已确定的行为

以[环境接口约定](/E:/动森/小丸子小镇/docs/architecture/environment-contract.md)和[编辑器交接](/E:/动森/小丸子小镇/docs/handoffs/C-town-editor.md)为基础：

- 全镇只有一套积雪进度。已确定雪量线性增长和融化、昼夜同速、后台和关闭期间暂停；阶段性外观变化不等于改变这套计时。
- 现有时长：下雪从无雪到满雪约 60 秒；满雪转晴约 300 秒融完；转雨约 60 秒融完。残雪中再次下雪，从剩余量继续。
- 天气与时段独立切换，不因换时段或停雪而清空雪量。
- 保留建筑原始造型、配色、灯光、入口和独立室内；无雪时恢复原有画面。
- 保留资产 ID、布局、编辑操作、撤销、保存及新旧文件兼容。测试使用隔离存档。
- 放置、旋转、移动、删除与撤销后，积雪正确跟随，不留下旧位置的雪壳。
- 可见雪面与降水落点一致。稀疏覆盖阶段的空隙不能仍被当成一整块高于地面的雪板；变化后的雪面查询应与显示同步。
- 保留实例资源隔离，不因更新或删除一栋建筑而影响其他实例。

## 六 验收标准

### 第一轮 小样画面

- 三个小样均可旋转、缩放并连续调整雪量；提供同一机位的无雪、零星附着、连续薄雪、厚雪截图和一段连续变化演示。
- 初期能辨认原路面和屋顶质地，不出现点击下雪后整片发白。
- 薄雪已连续覆盖底色，但厚度仍薄，能看出实际屋面和叶团的起伏；厚雪逐渐填平细小凹陷，保留大轮廓。
- 路面、屋顶、灌木有各自合理的积雪形状，不能用三个不同高度的白板代替。
- 从低角度查看屋檐、灌木叶团与根部、路面边缘，底部贴合，没有悬空、错误穿插及缺失侧壁。
- 使用符合小镇风格的光照展示接触和体积，不靠过曝或整片自发光隐藏缺陷。
- 融雪连续，雪消失后原材质和装饰正确恢复。

### 第一轮 小样定向检查

- 定向检查覆盖增长、厚度变化、侧壁朝向与贴合，不能只检查“存在雪网格”和“没有报错”。
- 检查变化后的可见雪面与降水落点查询一致，稀疏雪斑之间的空隙不能仍按完整白板计算。
- 验证预览未读写用户正式地图存档，未改变正式地图的运行行为。
- 记录小样场景的性能观察和局限，不把小样通过宣称为全镇、满地图或手机端通过。

### 第二轮 正式地图检查

- 检查正式地图与建筑接缝、草叶埋没、入口和招牌可辨，以及日夜雪面表现。
- 检查正式场景中可见雪面与雪花、雨滴落点一致。
- 检查放置、旋转、移动、删除、撤销及多实例隔离。
- 检查保存、重新载入与导入导出维持已有环境和存档规则。
- 对比同场景修改前后的性能，记录实际观察范围与尚未覆盖的场景。

交付分别报告实际改动、运行检查、截图或演示、待用户认可的画面。测试通过不能替代用户美术验收。服务启停、整项目回归、提交、推送和发布继续按用户具体授权执行。
