## 已确认的问题

### 1. 旧离线打包器把整个 dist 的 JS 收入每个页面

位置：`scripts/standalone.mjs:5`、`:7`、`:14`、`:19`。

脚本先递归搜集整个 `dist` 的 JS，再根据是否带 `--walk` 选择页面入口。因此后续增加的编辑器、樱家预览等模块，也被放进原便利店和旧散步的离线 HTML import map，即使这些入口不会导入它们。

当前静态计算：

| 离线入口 | 实际依赖模块 | 当前打包器收集模块 | 多收模块 | 多收的原始 JS 字节 |
| --- | ---: | ---: | ---: | ---: |
| 原便利店 `dist/scene.js` | 21 | 49 | 28 | 150,354 |
| 旧散步 `dist/walk/main.js` | 28 | 49 | 21 | 170,849 |

字节数为当前源码原始大小，不是重新打包后的最终 HTML 体积；Base64 还会增加体积。未引用的模块不会因此自动执行，但会增加离线文件大小和解析 import map 的内容。

建议：仅沿选定页面的依赖链打包；`scripts/package-sakura.mjs:5` 已有递归收集依赖的实际做法可参考。保留旧入口，改打包范围即可。

### 2. 新编辑器额外请求四种当前不使用的旧建筑

位置：`dist/town/assets/index.js:3` 至 `:6`；调用入口为 `dist/town/editor/catalog.js:1`、`convenience-scene.js:3`。

通用入口静态导入咖啡店、书店、普通住宅和小公园，而编辑器当前只创建便利店和四种道路。隔离 Chrome 确认 `/editor-preview/` 确实请求了这四个旧建筑模块；四个文件合计 8,992 原始字节。

这属于额外下载和模块求值，不代表四种建筑都已创建或正在渲染：实际模型创建仍发生在 `createBuilding()` 调用时。

建议：保留旧散步使用的通用入口，让编辑器只加载所需建筑与规格，同时保留实例缓存及门动画的既有行为。无需删除四种旧模型，也无需另造一套复杂资产架构。

### 3. 门动画的阴影更新判断已没有区分作用

位置：`dist/editor-preview/main.js:55`、`:56`。

第 55 行在门开合变化时设置 `shadowMap.needsUpdate=true`，紧接着第 56 行每帧无条件设置同一个值。就当前流程而言，第 55 行用于比较门状态的临时值和条件判断不会改变结果。

建议：若保留每帧刷新阴影，删除这一小段重复判断即可。不要仅为清理残留就关闭每帧阴影；草叶动画是否依赖实时阴影需要单独检查。

### 4. 未消费的旧调色板常量

位置：`dist/world.js:9` 的 `palette`。

当前项目运行代码和开发脚本里没有该导出的实际消费者；其余同名命中只是说明文字。该对象属于少量闲置定义，删除收益很小，可在后续窄范围清理时一并处理，不值得单独做大改动。

## 建议清理顺序

1. 先缩小旧离线包的收集范围，验证断网打开和必要操作。
2. 再消除编辑器对四种旧建筑的额外加载，验证便利店完整街角、缓存和门动画。
3. 清理无效阴影判断、闲置常量，更新过期说明。
4. 是否退役旧散步页以后单独决定；这一步会影响仍可用的功能，不能仅凭年代删除。

本报告不声称做过完整性能剖析、逐函数死代码证明或手机验收，也没有把删除历史备份列为代码优化。
